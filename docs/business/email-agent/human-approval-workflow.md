# DriverNord — Human Approval Workflow

**Date:** 2026-05-17
**Invariant:** No email is sent without explicit founder approval. This rule does not change in V1 or V2.

---

## Status Lifecycle

```
NEW
  │
  ▼
CLASSIFIED        ← agent assigns category, confidence, language
  │
  ▼
DRAFTED           ← agent generates summary, extracted fields, compliance flags, draft reply
  │
  ▼
NEEDS_FOUNDER_REVIEW    ← always — requiresHumanApproval: true is hardcoded
  │
  ├─► APPROVED_TO_SEND  ← founder reads draft, approves it as-is or with edits
  │       │
  │       ▼
  │     SENT            ← founder sends manually via Zoho (or system sends in future phases)
  │       │
  │       ▼
  │     CLOSED          ← outcome logged
  │
  ├─► ESCALATED         ← founder decides this needs lawyer, special handling, or company owner decision
  │       │
  │       └──► CLOSED after resolution
  │
  └─► IGNORED           ← spam, irrelevant, or founder decides no reply is needed
          │
          └──► CLOSED
```

---

## Status Definitions

| Status | Description | Who sets it | Next valid statuses |
|--------|-------------|-------------|-------------------|
| `NEW` | Email received, not yet processed | System / founder | CLASSIFIED |
| `CLASSIFIED` | Agent has assigned category and confidence | Agent | DRAFTED |
| `DRAFTED` | Agent has generated draft reply | Agent | NEEDS_FOUNDER_REVIEW |
| `NEEDS_FOUNDER_REVIEW` | Awaiting founder decision | Agent (always) | APPROVED_TO_SEND, ESCALATED, IGNORED |
| `APPROVED_TO_SEND` | Founder approved the draft | Founder | SENT |
| `SENT` | Reply was sent to the original sender | Founder (manual) | CLOSED |
| `ESCALATED` | Forwarded for special handling | Founder | CLOSED |
| `CLOSED` | Thread complete — no further action | Founder / system | — |
| `IGNORED` | No reply warranted | Agent (SPAM) or Founder | CLOSED |

---

## Founder Decision Checklist (per email)

When reviewing a triage result, the founder checks:

1. **Is the classification correct?** If not, override and rerun or classify manually.
2. **Are there compliance flags?** If yes, read the flag carefully before approving the draft.
3. **Is the draft safe?** Verify no job guarantee, no staffing claim, no official verification claim.
4. **Is the language correct?** Swedish email → Swedish reply.
5. **Does the draft match the intent?** Company inquiry → company draft, not driver draft.
6. **Are any extracted fields incorrect?** May indicate low confidence — draft may need editing.
7. **Does this need escalation?** If LEGAL_ADMIN flag or complaint flag is present, escalate before replying.

---

## Mandatory Escalation Triggers

The following always override the normal workflow and require founder to escalate before any reply:

| Trigger | What to do |
|---------|-----------|
| `complianceFlags` includes `LEGAL_GDPR_REQUEST` | Do not reply substantively. Send acknowledgement only. Forward to lawyer. |
| `complianceFlags` includes `LEGAL_COMPLAINT` | Do not reply substantively. Assess with lawyer if appropriate. |
| `complianceFlags` includes `ESCALATE_THREAT` | Do not reply. Log. Consider reporting if criminal threat. |
| `category` is `LEGAL_ADMIN` | Always escalate — do not handle via standard draft approval |
| `confidence` is `'low'` and content is sensitive | Do not approve draft — classify manually first |

## What Founder Approval Means

Approving a draft means the founder:

1. Has read the classification and agrees it is correct
2. Has read the draft and confirms it is safe to send
3. Has verified no compliance flags are unresolved
4. Has confirmed the draft is in the correct language
5. Has either accepted the draft as-is or edited it to their satisfaction
6. Takes responsibility for the content of the sent email

The agent produces a draft. The founder owns the reply.

---

## Sensitive Categories — Always Require Manual Review

These categories can never progress to APPROVED_TO_SEND without the founder reading the full email content:

- `LEGAL_ADMIN`
- Any email with `LEGAL_GDPR_REQUEST` flag
- Any email with `LEGAL_COMPLAINT` flag
- Any email with `ESCALATE_THREAT` flag
- Any email where `confidence === 'low'`

---

## Draft Reply Quality Standards

A draft generated by the agent must satisfy all of these before the founder is presented it:

1. Opens with correct greeting (formal Swedish: "Hej [Name]," or "Hej,"; English: "Hello,")
2. Acknowledges the email's intent in one sentence
3. Explains what DriverNord does / can do — without false claims
4. States a clear next step for the sender
5. Closes with: "Med vänliga hälsningar, DriverNord" (Swedish) or "Best regards, DriverNord" (English)
6. Contains no personal data from other drivers
7. Contains no price commitments not authorized by the founder
8. Contains no promises about supply, timelines, or outcomes

---

## Logging

At minimum, each processed email is logged with:

- `email_id` — unique ID assigned on receipt
- `category` — assigned classification
- `confidence` — high / medium / low
- `complianceFlags` — any flags raised
- `status` at final resolution — SENT / ESCALATED / IGNORED / CLOSED
- `action_taken` — what the founder decided
- `processed_at` — timestamp
- `sent_at` — if applicable

In V1 (no Supabase integration): log to console / local file.
In V2+ (Supabase integration): log to `email_triage_log` table (future schema proposal in implementation roadmap).

---

## No Unattended Sending

The email agent must not send any email without the founder being physically present and making a deliberate send action. This means:

- No scheduled email sends
- No "send in 5 minutes unless cancelled" patterns
- No send-on-status-change triggers
- No send from API routes triggered by webhooks alone

Even in future phases where SMTP integration exists, the send action must require a deliberate founder click on a confirmation UI or a deliberate CLI command confirming the email ID.
